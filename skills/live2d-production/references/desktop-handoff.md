# Astra 与 Terra 的交接

**一次交付一个可继续工作的环节，而不是每点一下就问一次。** Astra 持有阶段决策和最终验收；Terra ultra 是原生界面的执行者。生图、普通文件处理与曲线编写不需要占用桌面。

### 派发

用户要执行桌面流程时，先确认项目记录中的唯一 GUI 所有者；若已有合格的 Terra 会话，用 `followup_task` 继续，不另开第二个操作者。没有可用所有者时，用允许指定模型的通用角色，参数为 `model: "gpt-6.1-terra"`、`reasoning_effort: "ultra"`、`fork_turns: "none"`。使用新会话要给全简报，不传旧窗口句柄和像素坐标。固定模型/推理强度不符的角色不选；不把 priority 当作 Fast。

**可直接套用的简报**：`你是本阶段唯一 GUI 操作者。项目根/阶段记录：…；只改工作副本：…；母图/不可改：…；本次软件、目标对象与动作：…；完成的可见条件：…；输出与交给谁：…。保持用户原档和现场；受阻时保留最后成功状态，并继续无冲突事项。` 例如交给 Photoshop 的不是“优化眼睛”，而是“用批准的完整虹膜修载入 PSD，保留母档，移开眼睑时能看到完整边界，合回中性时眼位不变”。

Astra 在 Terra 操作期间做不冲突的事（动作设计、资源引用、交付说明等）。同一 PSD、同一 Cubism 模型或同一桌面输入流只有一个写入者；换软件按上一步产物路径交接。GUI 是一项任务的主体时才派 Terra；普通脚本/研究若需另派，用 `gpt-6.1-sol`。角色或工具确实不可用，保留影响的任务，不偷偷改成 Luna 或声称已用 Terra。

### 启动、控制与恢复

- 分清**打开软件**、**绑定窗口**和**获准操作应用**。用户已要求打开程序时，先查是否已有对应窗口；没有则可用已核实的正常启动入口打开指定工作副本。窗口出现以后，由 Terra 用当前提供的原生 Computer Use API 绑定实际目标并确认文档名。程序进程存在不代表文件载入或控制成功。
- 加载当前 Computer Use 技能与其必读规则。用该次接口文档，不硬套旧 API 或坐标；菜单/属性优先用能辨认的控件，画布拖拽用一次新观察支撑一次输入。输入后捕获失败不等于输入未执行，恢复视图后先看结果，不重放拖动。不使用固定主屏截图服务或脚本模拟点击。
- 宿主应用访问超时与用户未授权、编辑器崩溃是不同问题。记具体应用、错误及哪一步没发生；不反复弹相同请求、不改安全策略绕过。用户要求不用 Computer Use 的阶段可由本人点击，Astra 仍完成文件工作。
- 用户说暂停、实际按物理 Esc 或桌面控制被停止：立即停止输入。保留窗口、不替未知编辑保存或撤销；记“磁盘已保存”和“只在内存”分别是什么。仅整理技能、写说明不解除暂停。
- 用户要求半小时续作时，通过当前调度工具复用同一线程的心跳。提示词写入项目状态入口、当前副本、唯一 GUI 所有者、恢复与结束条件：有人正常工作时不抢界面，未变静默；遇暂停不能自动恢复，完成后停用。定时器不是操作许可。
